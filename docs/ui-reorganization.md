# 사용자 시나리오 기반 UI 재배치

## 문제와 목표

홈 소개, 검색, 지도, 공 던지기, 후보 목록, 관광 상세가 한 페이지에 연속으로 노출되어 사용 목적이 섞인다. 한 화면에는 하나의 주 작업만 두고, 공통 메뉴로 다른 작업에 직접 이동한다. depth는 DOM 중첩이 아닌 내부 화면 탐색 계층으로 정의한다. 홈1 → 기능2 → 상세3을 최대치로 한다.

## 사용자 시나리오

| 사용자와 의도 | 행동 흐름 | 화면 결정 | 성공 기준 |
| --- | --- | --- | --- |
| 처음 방문한 사용자: 무엇을 할지 선택 | 홈 → 직접 찾기 / 랜덤으로 고르기 / 후보 확인 | 홈에는 소개와 진입 카드만 배치 | 검색폼·공·후보리스트가 홈에 노출되지 않음 |
| 목적지가 있는 사용자: 지역과 취향으로 탐색 | 여행지 탐색 → 필터 → 목록 → 지도 전환 | 검색 전용 화면, 목록/지도 탭은 동일 화면 | 필터와 결과를 유지하며 모달/새 페이지 없이 전환 |
| 목적지가 없는 사용자: 던지며 후보 수집 | 랜덤 여행 → 범위/단위 선택 → 스핀/던지기 → 후보함 바로가기 | 공과 지도 중심의 전용 화면, 후보 개수와 이동 링크만 표시 | 던지는 동안 다른 기능에 방해받지 않고 여러 후보를 추가 |
| 후보를 모은 사용자: 비교하고 정리 | 여행 후보함 → 삭제/실행 취소 또는 관광정보 | 독립 후보 목록, 빈 상태에 랜덤 여행 진입 버튼 | 후보가 새로고침 후 복원되고 다른 화면에서도 목록 유지 |
| 후보를 정한 사용자: 실제 장소 확인 | 여행 후보함 → 지역 관광정보 → 지도 마커/길찾기 | 지역 상세는 3단계, 지도/관광목록은 같은 화면 | 뒤로 가면 후보함으로 복귀; 관광지 선택으로 4단계 생성 안 함 |
| 계정 작업 사용자: 가입/로그인/복구 | 공통 계정 메뉴 → 계정 패널 | 독립 전역 계정 작업; 가입·로그인·복구는 동일 대화상자 교체 | 모달 위 모달 없이 기존 인증 흐름 유지 |

## 화면 구조

| 깊이 | 화면 | 주요 내용 | 경로 |
| --- | --- | --- | --- |
| 1 | 홈 | 소개, 직접 찾기/랜덤 여행/후보함 진입 | #home |
| 2 | 여행지 탐색 | 검색 필터, 목록/지도 전환 | #explore |
| 2 | 랜덤 여행 | 전국 지도, 공, 조작, 결과와 후보 개수 | #random-trip |
| 2 | 여행 후보함 | 후보 카드, 관광정보 진입, 삭제/실행 취소 | #candidates |
| 3 | 지역 관광정보 | 선택 지역 제목, 지도, 관광목록, 후보함 복귀 | #candidate/{지역코드} |

공통 메뉴는 홈·여행지 탐색·랜덤 여행·여행 후보함의 4개다. 모바일도 메뉴를 숨기지 않고 가로 넘침 없이 제공한다. 현재 메뉴와 이동 경로, 화면 제목을 표시한다. 계정 패널은 전역 메뉴에서 접근하는 독립 작업이며 기능 화면의 상세를 추가로 중첩하지 않는다.

## 상태와 예외

- 주소 직접 진입/새로고침/브라우저 앞뒤 이동 지원. 잘못된 주소는 홈, 삭제되었거나 존재하지 않는 후보 상세는 후보함으로 이동하고 이유를 안내한다.
- 검색 조건·표시 방식·공 지도 범위와 후보는 페이지 전환에도 유지한다. 비행 중 이동은 기존 취소 규칙을 따른다.
- 후보 상세에서 나가면 진행 중 요청을 취소하고 늦은 응답을 무시한다.
- 숨긴 화면은 포커스·접근성 트리에서 제외한다. 이동 시 제목으로 초점을 옮긴다. 현재 메뉴에 aria-current를 제공한다.
- 360/768/1440px, 키보드, 모션 감소 환경에서 주요 시나리오를 검증한다.

## 구현 순서

1. UIA 요구사항과 실패 테스트 작성.
2. 기존 상태를 유지하는 가벼운 해시 기반 화면 전환과 공통 메뉴 추가.
3. 랜덤 화면에서 후보함·관광상세 분리, 검색 결과는 목록/지도 전환.
4. 브라우저 이동·직접 진입·잘못된 상세·반응형 검증 후 전체 하네스 실행.

전국 경계 연도·실 API 설정·로컬 계정 한계는 기존 표시를 보존한다. 물리/지도/관광 공급자 구현은 이번 UI 작업에서 교체하지 않는다.
