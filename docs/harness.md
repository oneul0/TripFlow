# 민감정보 도입 전 개발 하네스

## 실행 경계

`npm run harness`는 단위·DOM 테스트 → 샘플 빌드 → 격리 E2E 순서로 실행하며 실패 시 중단한다. 필수 기능의 실 API 검증은 별도 수동 단계이며 이 명령의 통과만으로 완료 판정하지 않는다.

- `npm run dev`: 샘플 모드. 환경 파일에 키가 있어도 실연동하지 않는다.
- `npm run dev:live`: 명시적인 관광 API 연동. 키 누락 시 시작 실패 안내.
- `npm run build`: 샘플 빌드. 외부 API 설정을 빈 값으로 고정한다.
- 실연동 빌드가 필요하면 `npm run build -- --mode live`를 명시한다. 이는 지정한 관광 API 키를 브라우저에 공개한다.

Vite 환경변수 자동 노출을 끄고 모드·관광 API 키·관광 API 주소만 명시적으로 주입한다. JavaScript 키처럼 공개 사용이 허용된 설정만 클라이언트에 넣는다. `VITE_`나 `.env`는 비밀 보관 장치가 아니다. 서버 전용 키·실제 개인정보·운영 계정은 지금 프론트엔드에 넣지 않는다. 이후 같은 모놀리식 서버의 인증·비밀 관리 경계에서 처리한다.

## 테스트 격리

단위 테스트의 기본 fetch는 실패한다. 테스트마다 fixture 응답 함수를 주입한다. E2E는 5174 포트에 harness 서버를 새로 실행하며 5173 개발 서버를 재사용하지 않는다. 브라우저 컨텍스트는 각 테스트에서 분리되고 외부 HTTP 요청은 차단된다. 서비스 워커·스크린샷·영상·트레이스를 끄며 테스트 입력에는 example.com과 합성 계정만 사용한다. 이 차단은 테스트 격리이며 운영 보안이나 OS 네트워크 격리를 대체하지 않는다.

로그는 기존 허용 목록을 유지한다. 이메일·비밀번호·복구 코드·좌표·검색어·키·전체 외부 응답을 로그에 추가하지 않는다. 계정 저장은 합성 데이터용 로컬 데모로 남는다.

## 변경 작업 순서

요구사항 ID와 수용 기준 → 실패 테스트 확인 → 최소 구현 → 회귀 검증 → 실제 연동 별도 확인. SDK 기능은 어댑터 밖으로 퍼뜨리지 않고 자동 테스트에서는 대체한다. 실제 연동 로그나 화면 캡처를 공유하기 전에 값 노출 여부를 확인한다. 비밀값을 도구 출력·문서·fixture에 복사하지 않는다.

카카오 공개 JavaScript 키와 지도 모드만 허용 설정으로 추가했다. `npm run dev:map`은 지도만 실연동하고 관광 키를 노출하지 않는다. SDK 대체 테스트와 별도 실연동 검증을 함께 수행한다. 기본 실행·하네스는 카카오 키를 주입하지 않는다.

## 완료 조건과 남은 경계

HAR-001~006 명세: `specs/features/harness.md`. 모드·환경 주입·네트워크 차단·로그 허용 필드·기존 회원 및 검색 흐름을 자동 검증한다. 하네스는 비밀 문자열 전체 탐지, 운영 서버 인증, 암호화된 개인정보 저장, 접근 통제를 구현하지 않는다. 실제 민감정보 도입 전에 서버 설계와 검증이 필요하다.
