# TripFlow

HTML·CSS·JavaScript·Bootstrap으로 구현한 국내 여행 탐색 프론트엔드. 하나의 앱과 빌드로 유지하는 모듈형 모놀리식이며 관광 데이터·검색·로그·AI 제공자를 함수 계약으로 교체한다.

작업 시작 전 [필수 프로젝트 규칙](../AGENTS.md)을 읽는다. 규칙 일부의 자동 검증은 `npm run rules:check`, 전체 검증은 `npm run harness`로 실행한다.

## 실행

Node.js 22.12 이상 또는 24 LTS를 사용한다.

```powershell
npm ci
npm run dev
```

http://127.0.0.1:5173 에 접속한다.

민감정보 도입 전 검증은 `npm run harness`로 실행한다. 기본 실행과 빌드는 샘플 모드이며 외부 API 설정을 노출하지 않는다. [하네스 실행 경계](../docs/harness.md)를 참고한다.

```powershell
npm test
npm run test:e2e
npm run build
npm run preview
```

브라우저 테스트는 설치된 Microsoft Edge를 사용한다. 다른 환경에서는 `playwright.config.js`의 channel을 변경하고 필요한 Playwright 브라우저를 설치한다.

## 공공데이터 설정

.env에 디코딩된 관광공사 키를 TOUR_API_KEY로 설정하고 npm run dev:live로 실행합니다. 관광 키는 같은 개발 서버의 /api/tour 경로에서만 사용하며 브라우저에 전달하지 않습니다. 기본 dev와 build는 샘플 모드를 유지합니다. live 정적 빌드만 별도로 호스팅하면 서버 경로가 없으므로 동작하지 않습니다. 운영 서버 배포는 아직 구성하지 않았습니다.

출처: [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do). AI 추천은 현재 연결하지 않았다.

## 카카오 지도 탐색

`.env`에 공개 JavaScript 키 `VITE_KAKAO_MAP_APP_KEY`를 설정하고 SDK 도메인 `http://127.0.0.1:5173`을 등록한 뒤 `npm run dev:map`으로 실행한다. 카카오 로그인 리다이렉트 URI는 지도 기능에 필요 없다. 지도 전용 모드는 샘플 관광정보를 사용한다. `npm run dev`와 기본 빌드는 키를 주입하지 않는 샘플 경계 지도다.

서울 25개 구 선택, 구역별 밝기와 경계 안 그라디언트, 클러스터·마커와 목록 연동, 지도 범위 필터를 제공한다. 경계는 2013년 개발 기준 데이터이며 전국 집계와 최신 경계는 후속 범위다. [지도 구현·검증](../docs/map-explorer.md), [데이터 출처](../docs/third-party/seoul-maps.md)를 참고한다.

## 구조와 개발 방식

랜덤 여행은 주 메뉴의 **랜덤 여행**에서 시작한다. Three.js가 공의 3D 회전과 원근을, cannon-es가 강체·중력·각속도·착지를 처리한다. 원형 드래그로 돌린 뒤 위로 쓸어 놓으면 첫 착지 지역을 후보함에 담는다. 전국 시도→시군구→읍면동 선택, 휠/핀치 확대, 키보드 조작, 후보 삭제·실행 취소·복원을 지원한다.

**전국 17개 시도·251개 시군구·3482개 읍면동, KOSTAT 2013 경계**를 제공한다. 최신 명칭·경계는 아니며 출처와 연도를 표시한다. 후보의 관광정보는 해당 시도 최대20개 미리보기다. 기본 실행은 합성 샘플, `dev:map`은 카카오지도, `dev:live`는 관광공사 GW와 카카오를 사용한다. 관광공사 실 API 조회를 확인했다. 카카오 SDK는 등록 도메인과 키 설정에 따라 연결한다. [실행·연동 제한](../docs/random-trip.md), [RND 명세](../specs/features/random-trip.md)를 참고한다. 후보는 현재 브라우저에 저장하며 계정/기기 동기화는 지원하지 않는다. 좌표·입력 경로를 저장/로깅하지 않는다.

2026-10-02 RND v2 검증: `npm run harness` 정상 종료 — 단위·DOM 56개, E2E 13개, 빌드 통과. `npm run rules:check` 14개 통과. 스핀 드래그·원근 정렬·전국 읍면동·관광정보·360/768/1440px를 검사했다. 번들 크기 경고는 남아 있다(JS 약2.93MB, gzip691KB; 전국 경계와 3D/물리 라이브러리 포함). 실제 터치 기기의 감도와 실연동 성공은 별도 확인 사항이다.

- `src/app.js`: 단일 조립 지점
- `src/modules`: 관광·회원 서비스
- `src/adapters`: 관광 공급자, 검색·로그·AI 제공자, 저장소
- `src/contracts.js`: 확장 인터페이스 JSDoc
- `src/ui.js`, `src/tokens.css`, `src/design-system.css`: 반응형 화면과 사용자 흐름
- `specs`: 수용 기준과 계약, 테스트 추적
- `tests`, `e2e`: 서비스·DOM·브라우저 테스트

변경은 명세 → 실패 테스트 → 최소 구현 → 리팩터링 순서로 진행한다. [아키텍처](../docs/architecture.md), [요구사항](../specs/requirements.md), [테스트 매핑](../specs/test-matrix.md)을 참고한다. 실제 AI·중앙 로그·검색 엔진은 동일 애플리케이션 서버 내부 모듈로 구현하는 후속 범위다.

code-review-graph는 `.tools/crg`의 로컬 도구이며 커밋하지 않는다. `.code-review-graphignore`로 의존성과 빌드 결과를 제외한다. 기존 CodeGraph와 별도 도구다. 현재 Git 저장소가 없어 증분 변경 발견과 diff 리뷰가 제한되므로 Git 초기화 전에는 `build --repo .`로 갱신한다.

검증한 화면 캡처는 `docs/screenshots/home-1440.png`, `docs/screenshots/home-360.png`에 저장되어 있다. 개발 서버 실행 중 `node scripts/capture.mjs`로 다시 생성한다. 기본 여행 이미지는 AI로 생성한 분위기 예시로 실제 관광지 사진이 아니며 각 이미지에 표시한다. API 사진이 정상 로드되면 실제 사진을 우선 표시한다.

## 여행 후기 게시판 (F110)

상단 **여행 후기**에서 분류·검색·페이지 탐색과 글 작성/수정/삭제를 제공합니다. 로그인 후 본인이 저장한 코스의 **후기로 공유**를 누르거나 작성 화면에서 코스를 선택하세요. 첨부는 방문 순서를 포함한 복사본으로 저장되어 원본 수정·삭제와 분리됩니다. 기존 글과 첨부 없는 글도 유지됩니다. 화면 깊이는 최대3입니다.

[통합 계약과 수용 기준](../specs/features/board-integration.md). 로그인 회원의 새 계획은 회원 ID로 소유권을 연결합니다. 이전 익명 체험 계획은 자동으로 회원에게 이전하지 않으며, 오래된 계획은 다시 저장해야 첨부할 수 있습니다.

현재 게시판은 같은 브라우저·origin의 로컬 데모입니다. 원격 게시/다중 사용자 권한 검증, 댓글, 이미지 업로드는 구현 범위에 포함되지 않습니다. 코스 첨부의 장소는 합성 데이터로 표시하며 실제 이동 거리·시간을 만들어 표시하지 않습니다.

2026-10-02 검증: 전체 harness 정상 종료(단위·DOM100개, E2E33개, 빌드), rules:check15개 통과. 이후 추가한 늦은 응답·HTML 출력 회귀 테스트도 통과(첨부 UI2개). 360/768/1440px 작성·조회·수정·삭제와 로그인 후 이어쓰기를 검증했습니다. 기존 번들 크기/JSON import 경고는 남아 있습니다. 외부 API 실연동은 이번 게시판 검증 대상이 아닙니다.

## 블록 코스 만들기 (F104 / CB-01~07)

여행지 탐색의 **코스 후보에 담기**로 장소를 모은 후 **코스 만들기**에서 추가·정렬·삭제·실행 취소합니다. 데스크톱 드래그와 모바일/키보드용 위·아래 버튼을 지원합니다. 시간·금액 조정에서 체류/장소 지출과 이전 장소로부터의 이동 시간/비용을 입력합니다. 알려진 값만 합산하며 미확인을 0으로 표시하지 않습니다. 순서를 바꾸면 이전 장소가 달라진 구간 추정치는 초기화됩니다.

저장한 코스는 새로고침으로 복원됩니다. 공유한 코스는 **내 일정으로 복사**하여 원본과 독립적으로 편집할 수 있고 게시판 **후기로 공유**에도 출처와 예상 합계가 유지됩니다. 실제 다른 사용자/기기 간 공유는 서버 단계로 남깁니다. 합계는 사용자 추정치이며 자동 길찾기·실제 요금 계산이 아닙니다. 첫 장소까지와 귀가 이동은 포함하지 않습니다.

[블록 코스 계약](../specs/features/course-blocks.md)이 기존 코스 UI의 점수/리뷰/상세조건 표시 계약을 대체합니다. 기존 코스·리뷰 데이터와 핵심 서비스는 삭제하지 않습니다. 후보는 사용자별로100곳, 코스는30곳까지 저장하며 중복 장소 방문은 지원하지 않습니다. 기존 코스 저장소 version1을 유지하고 후보 장바구니만 별도 version1 저장소를 사용합니다.

2026-10-02 검증: harness 정상 종료 — 단위·DOM107개, E2E32개, 빌드 성공. rules:check15개 통과. 360/768/1440px에서 후보 복원·정렬·합계·저장·공유·복사본 독립성, 데스크톱 드래그와 게시판 회귀를 검증했습니다. 점수/리뷰 화면의 기존 E2E는 새 블록 계약으로 대체했고 계산/리뷰 서비스 단위 검증은 유지했습니다. 기존 JSON import/번들 크기 경고는 남아 있습니다. 외부 API 실호출은 이번 변경 검증 대상이 아닙니다.

## 랜덤 여행 게임 보드 (RND-13~16)

수직 지도 보드에 화면 앞의 공을 던지는 방식으로 변경했습니다. Three.js와 cannon-es를 유지하며, 발사 세기는 순간 속도 대신 쓸어 올린 거리를 기준으로 제한합니다. 스핀 회전·커브를 유지하고 보드 밖으로 날아가는 극단 입력을 제한합니다. 가까운 육지는 최대90 보드 단위 안에서 보정하고 보정 여부를 안내합니다. 예상 착지점·목표 지역·발사 전 궤적은 사용자 요청에 따라 표시하지 않습니다. 실제 비행 궤적과 명중 효과만 표시합니다.

[수용 기준](../specs/features/random-gameplay.md). 테스트: random-gameplay(입력 상한/속도 독립/보정 범위), random-upgrade(수직 투영/강체 회전), random-trip-ui(예측 표시 없음/저장·취소), 기존 E2E(360/768/1440px·실제 쓸기·제주·읍면동). 검증: harness 단위·DOM111개/E2E32개/빌드 통과, rules:check15개 통과. 기존 빌드 경고와 KOSTAT2013 경계 한계는 유지합니다. 외부 API 실연동은 이번 검증 범위가 아닙니다.

RND-17: 공을 누른 채 움직이면 잡은 오프셋을 유지해 마우스/터치를 따라 움직입니다. 위쪽 제스처로 놓으면 놓은 위치에서 발사하고, 취소하면 원래 위치로 돌아옵니다. 예상 착지점은 계속 숨깁니다. 포인터 이동·취소 DOM 테스트와 발사 시작 위치 물리 테스트를 추가했습니다.

RND-18: 공의 시작 깊이를 지도보다 카메라 쪽으로 당겨 원근감을 강화했습니다. 화면 크기는 Three.js 카메라 거리로 연속 감소하고 착지 직전 지름은 시작의 약38%입니다. 잡기 좌표와 물리 발사 원점을 공통 상수로 맞췄습니다. 원근 단조 감소·크기 비율 테스트를 추가했으며 예상 착지점은 표시하지 않습니다.

BRAND-01: 서비스명을 TripFlow로 변경하고 제공받은 TripFlow-logo.svg 원본을 public/images/tripflow-logo.svg에 적용했습니다. 헤더·푸터 로고, 서비스 소개·회원가입·브라우저 제목을 변경했습니다. 저장소 키와 내부 이벤트/외부 API 애플리케이션 식별자는 기존 호환성을 위해 유지합니다. 테스트115개, E2E32개, 빌드 및 rules:check15개 통과. 기존 빌드 경고와 로컬 저장 데모 제한은 유지합니다.

UX-COPY-01: 사용자 요청에 따라 보정 ON/보정 적용, 브라우저 저장 데모 배너, 내부 지역 식별자, SDK 키·도메인 설정 등의 개발 메모를 사용자 화면에서 제거했습니다. 샘플·부분 조회·추정치·오류·재시도는 유지합니다. 저장과 공유가 같은 브라우저에 한정된 현재 구조는 그대로이며 실제 서버 공유로 변경한 것이 아닙니다. 개발 한계는 이 문서에서 관리합니다.

### 편집형 디자인 (EDIT-01~04)
크림·보라색 공통 토큰, 홈 지도 진입과 최신 이야기 3개, 사진 없는 게시글의 텍스트 목록, 760px 상세 읽기 폭, 데스크톱 왼쪽 지역 패널을 적용했다. 기존 검색·저장·코스 공유·랜덤 게임 동작은 유지한다. 자세한 범위: [디자인 명세](../specs/features/editorial-design.md).

MAP-INIT-01: 기본 지도 중심은 서울시청이며, 숨겨진 지도의 범위 계산은 표시 시점까지 보류한다. 화면 재배치 시 기존 중심을 보존한다.

RND-STYLE-01: 랜덤여행에 아케이드 프레임·플레이 방법·조작 패널·성공/재도전 상태 디자인 적용. 공 물리와 후보 저장 규칙은 유지한다.

RND-SPIN-01: cannon-es 각속도 감쇠를 공을 잡은 상태에도 적용하고, 잡기 테두리·제한된 반짝이 효과와 모션 감소 대체 표현을 제공한다.

CLUB-01: Aardvark 참고 디자인을 홈·탐색·커뮤니티·코스·후보함·계정·랜덤여행에 적용했다. 노랑/핑크/청록 색면과 검정 제목을 사용하며 TripFlow 로고·기존 기능을 유지한다. [명세](../specs/features/club-design.md).

RND-ZOOM-01: 최소 배율에서 더 축소하면 읍면동→시도 내 시군구→전국 지도로 돌아간다. 버튼·휠·핀치 공통 적용.

CB-PLACE-01: 코스 편집 상단에서 구성 장소와 방문 순서를 확인한다. 각 블록·후보·공유 상세에 유형·지역·주소·카카오지도 검색 링크를 제공한다. 주소는 신규 후보부터 저장하며 예전 코스의 누락 주소는 추정하지 않는다.

### 코스 만들기
`#course-editor`에서 후보 추리기 → 코스 구성 → 생성·티켓 받기를 순서대로 진행합니다. 지역·유형별 장소 후보를 고르고 블록을 연결한 뒤 저장된 코스를 PNG 티켓으로 내려받습니다. 공유와 후기 작성은 생성 결과에서 이어집니다. 후보와 계획은 기존 브라우저 저장 방식을 사용하며 기기 간 동기화는 제공하지 않습니다. 명세: `specs/features/course-workflow.md`.

코스 티켓은 항공권 스타일의 브랜드 헤더·절취선·방문 순서와 요약표로 표시되며 같은 디자인을 PNG로 저장합니다.
